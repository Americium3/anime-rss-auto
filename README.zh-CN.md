面向 Windows 的全自动季度番剧流水线：

```
bangumi.tv（在看列表）
     │  每 5 分钟轮询
     ▼
mikanani.me（解析番剧 → 单一字幕组的 RSS feed）
     │
     ▼
qBittorrent（RSS 自动下载规则，套用你的命名约定）
     │  硬链接镜像
     ▼
Jellyfin（按季度自动建库、季节封面、倒序排列）
     │  webhook：看完一集
     ▼
停止该集做种 + 在 bangumi.tv 上标记该集看过
     ▲
     └─ 取消勾选「看过」则两者一并撤销
```

只要在 bangumi.tv 上把一部番标成**在看**，其余的一切——订阅、下载、
Jellyfin 建库、看过状态回写——全部自动完成。或者只标成**想看**：它会在
开播当天自动提升为在看（先行版会被过滤掉）。

## 功能一览

| 模块 | 作用 | 开关 |
|---|---|---|
| **sync / watch** | bgm 在看列表 → mikan feed + qB 规则（保存路径 `<库>\<YYYY.MM>\<番名>`、季度标签） | 核心 |
| **开播自动追（premiere watch）** | 想看列表里的番在开播当天自动提升为在看（以 bgm 第一集放送日为门槛；可用 `premiere_times.json` 覆盖），并在面板弹开播横幅。先行版按名字（先行/予告）、大小（> 2 GB）、开播前发布日期三重剔除 | `premiere_watch_enabled` |
| **字幕组优先级** | 按你排好的优先级为每部番选一个字幕组；绝不重复下多个组 | `group_priority` |
| **番剧解析（show resolution）** | 用番的 `name_cn` / `name` 在 mikan 站内搜索定位其 feed，搜不到时再用 bgm 别名（别名 / 罗马字）——mikan 索引的是发布名/原名，所以显示中文名与之不同的番（如 `正后方的神威` vs. mikan 的 `从后面来的神威先生`）也能靠罗马字别名解析到。每个搜索词在原串搜不到时会自动去掉波浪号（～）重试——mikan 站内搜索对含 ～ 的查询一律返回空，否则「主标题 ～副标题～」式的番名会全军覆没。每个候选都以 mikan 页面的 bgm id 校验，名字再松也不会张冠李戴。连别名都对不上的顽固番可在 `mikan_overrides.json`（`bgm_id` → mikan `bangumiId`）里手动钉死，它被最优先查。**已开播**却仍解析不到的番会在面板弹出警告横幅——这是持续状态而非一次性事件，番一旦解析成功横幅自动消失——不再静默失败 | `unresolved_scan_enabled` / `mikan_overrides.json` |
| **手动解析（manual resolve）** | 「未匹配 mikan」横幅自带一个粘贴框：把 mikan 链接丢进去就能手动钉死这部番，不用再编辑 `mikan_overrides.json`。贴**番组页**链接——或页面上带番组反查的**剧集页**链接——会写入 override 并走正常订阅管线（feed + 规则 + mikan 订阅，文件夹惯例完全一致）；剧集页链接还会**立即下载你贴的那个资源本体**（你挑的就是它，即使规则的组过滤词永远不会匹配到它）。**没有**番组反查的剧集页（一次性资源：冷番补完式的剧场版/特别篇，在 mikan 上不属于任何番组、RSS 永远匹配不到）或裸磁力链则作为一次性导入：磁力直接交给 qB、落进该番的库文件夹，同时在 `manual_imports.json` 记下 `infohash → bgm subject`，让 mark-watched / jfhook / autocomplete 把这个无规则的种子当成规则下载的一样认领（单本篇集的番不需要文件名里有集数——剧场版规格）。成功后想看自动升在看、横幅立即消失。也可脚本化：`python anime_rss.py resolve --bgm-id N --url <链接>` | 常开（就是横幅的第二个按钮） |
| **同组多版本取舍** | 有些组一集会并行放多个版本——按**来源**（Baha / CR / ABEMA / B-Global…）或按**字幕语言**（简日双语 / 繁日双语，也写作 JPSC / JPTC / CHS / CHT）。黑名单里的源（ABEMA、B-Global）写进每条规则的 `mustNotContain`，在 feed 层直接拒、永不下载；同一集若同时下到多个版本，下载后只保留最优先的一个、删掉其余（含文件）。取舍按维度字典序（先源、后语言、末修正版：Baha ＞ CR，简 ＞ 繁，原始版 ＞ V2/V3）。语言维度是**每档一组同义标记**，CJK（简/繁）和拉丁缩写（SC/TC/CHS/CHT/GB/BIG5，含 JPSC/JPTC 这种粘连写法）都能认，又不会误伤 disc/watch 之类词中段。修正版是最低优先级的 tiebreaker：同一集若既有原始版又补发了 `[V2]`/`04v2`，保留你已下好的原始版、删掉后来补发的修正版；孤零零的 V2（没有兄弟版本）绝不误删。无标签的种子不误伤，仅对分界季度之后的番生效。可单独跑 `python anime_rss.py dedup [--dry-run]` | `prefer_variant_enabled` / `source_blacklist` / `source_priority` / `lang_priority` |
| **防生肉误抓** | 兜底字幕组（不在 `group_priority`、无自定义过滤词）原本 `mustContain` 为空 = feed 里啥都收，会抓到 mikan 交叉发布的无中文字幕流媒体生肉（如带该番英文译名的 Netflix 双语版）。两道防线：这类组的新规则要求标题含中文字幕标记（`cjk_sub_required`，单个 `\|`-或串，feed 层拒生肉——`CR` 与 `Baha` 也在白名单内，因为 Crunchyroll 与巴哈姆特动画疯版都带官方中文字幕（CR 内封简繁、Baha 内嵌繁中）、标题只标平台不标语言，避免「只搬运这些平台」的番被整条误挡；无中文翻译的 ABEMA/B-Global 仍由 `source_blacklist` 排除），且任何下载到的、名字命中生肉平台标记（`hard_reject_tags`，如 `NF WEB-DL`）的种子无条件删除、不受「唯一版本」保护。白名单扩充后，存量兜底规则会在下一轮自动原地升级（按前缀识别旧版默认串，组自定义过滤词绝不误改）。两者都守季度分界红线；且订了 mikan 生肉桶的番整番豁免（`raw_subgroup_ids`——mikan 把所有无标记投稿归到同一个全站组 id 202，组名就叫「生肉/不明字幕」）：规则指到那里就是点名要生肉，硬套这两道防线等于每轮把点名要的那一集下下来再删掉，永远如此，而且只在日志里说一声 | `cjk_sub_required` / `hard_reject_tags` / `raw_subgroup_ids` |
| **mikan 换条目（re-file）** | 解析时 mikan 上还没有该番条目的，会落到最松的一层按名字匹配——分割成两半的季度，匹到的就是**另外那一半**。据此建的规则反过来给这次猜测背书：解析快路径信任「有活规则用着这个 bangumiId」的任何映射，于是猜测永远熬过 TTL；等 mikan 后来给该番开了自己的条目，旧 feed 就在半季处静静断掉，什么错都不报。所以未经确认（`low`）的映射即便有规则撑着也照走 24 小时 TTL 重查；一旦查出换了条目，规则跟着搬：同文件夹、同字幕组、同 `previouslyMatchedEpisodes`（已下好的集绝不重下），只换 `bangumiId`，旧 feed 在无人引用后摘掉。被两个在看条目同时认领的 feed 一律不动——搬了就等于把另一半退订。已确认的映射（mikan 页面点名了 bgm 条目）不可能搬，且零网络开销 | 常开 |
| **ANi 宽限期保险丝** | 番剧首次出现在 mikan 时若最高优先组还没发布，先等 N 小时再锁定次优组（等待期漏掉的剧集会从 feed 补抓回来） | `ani_grace_hours` |
| **对账（reconcile）** | 番剧转为 看过/抛弃 → 删 qB 规则（保留文件）；彻底移出收藏 → 退订 + 删文件 | `purge_dropped_files` |
| **旧番分界线** | 早于分界季度的番永不触碰——不增、不删。跨季番（半年番/年番）只要还在播就继续自动管理，依据权威的放送日程判定（bgm 逐集 airdate：末集放送日 ≥ 今天即视为在播；AniList `status` 兜底）。播完后回退成手动老番——所以还在更新的 2-cour/年番不会因为开播季度落在分界线之前就被冻结，而很久前完结的长番也绝不会被重新触碰。个别番也可按 bgm id 手动钉为「当前」 | `skip_before_season` / `pin_current_bgm_ids` |
| **分割季断号接续** | 字幕组按整季连续编号，而 bgm 把这一季拆成两个条目、后半从第 1 集重新开始 —— 于是 ANi 的 `第四季 - 13` 谁都对不上：前一个条目只到 11，后一个条目自己的编号管它叫 2、全系列 `sort` 管它叫 79。这一集既不会停做种也不会标看过，唯一的痕迹是一行跳过日志。现在：当某个编号在 mikan 页面所指的条目的**两套编号里都找不到**时，改用「解析到同一个 mikan 条目的另一个 bgm 条目」重试，并减去前一个条目的本篇集数作为偏移。四个条件全部满足才动手：两个条目解析到同一 feed；该编号在前一个条目里**不**成立（两半是重叠的，都有第 5 集）；减去偏移后在后一个条目里成立且 ≥1；前一个条目的完结日期早于后一个条目的开播日期 —— 最后一条同时定死了方向，万一 mikan 页面指的是后半，它会拒绝而不是瞎猜 | 常开 |
| **mark-watched** | 你在 qB 里暂停一个已完成的种子 → 该集在 bgm 上标看过（基于状态跳变，绝不批量误标） | `mark_watched_enabled` |
| **看完自动收（autocomplete）** | 一部在看番的**本篇全部集**都在 bgm 标了看过（你手动，或 mark-watched / jfhook 逐集自动标）→ 整部自动升为看过，随后由 reconcile 接手（删 qB 规则、保留 mikan 订阅 + 本地文件），并在面板弹「本季看完」横幅（带一键「去 bgm 评分·写评语」直达该番条目页的链接）。两道保险：读的是**逐集**收藏状态（不用不可靠的 `eps` 总数），且只有 finale 已开播（所有本篇 airdate ≤ 今天）才收——所以一部还在播、你恰好把已列出的集都看了的番绝不会被提前收掉。和其它写入 pass 一样遵守旧番分界线。可单独跑 `python anime_rss.py autocomplete [--dry-run]` | `autocomplete_watched_enabled` |
| **Jellyfin 镜像** | 把新剧集硬链接进 `<镜像>\<季度>\<番名>\Season 01\`（0 额外占空间，不碰做种） | `jellyfin_mirror_enabled` |
| **Jellyfin 自动建库** | 新增季度文件夹 → 自动建库、生成封面、倒序排列 | `jellyfin_autolib_enabled` |
| **Jellyfin 联动删除** | 源库删掉某季度 → 镜像 + Jellyfin 库一并删除；并按**单文件**：某集视频若源文件已不存在（如被同组多版本取舍删掉、或切换字幕组换掉），其镜像孤儿硬链接一并清除，Jellyfin 不再显示旧版本（多重安全闸：源根缺失/为空即中止，某番源里 0 视频则整番跳过） | `jellyfin_mirror_delete_enabled` |
| **Jellyfin 空系列自愈** | 镜像重建竞态导致某系列在 Jellyfin 里变空壳、点播报「Unable to find a valid media source」→ 每轮 1 次调用查出「0 集但磁盘有视频」的系列并递归刷新修好（正常番零开销，带扫描进行中安全闸） | `jellyfin_heal_empty_enabled` |
| **Intro Skipper 触发** | 晚上 9 点入库的一集，按插件默认只能等下一次夜间批扫才有跳过按钮，所以硬链接进镜像的那一刻就顺手踢一脚 Intro Skipper 的检测任务。三点让它不至于变成 CPU 负担：先等镜像刚触发的那次库扫描回到 `Idle` 再动手（扫描还在跑时触发＝对着「还没收录这一集」的库做指纹，白跑几十分钟），任务已在运行时绝不重复触发，且两次触发间至少隔 `intro_skip_min_gap_minutes`。等待在独立线程里进行，本轮 sync 的后续步骤一步都不耽误。分析范围由 `analyze_skip_before_season` 划定：镜像里早于该季度的文件夹——以及 `Ancient` 这类非季度目录——会被写进插件自己的 `PathExclusions`。那是一份**黑名单**（按路径前缀匹配），所以将来新建的季度默认就在分析范围内，不需要任何维护。这份列表与「自动建季度库」在同一处维护（单一事实源），你自己在镜像之外添加的条目绝不会被动。可单独跑 `python anime_rss.py analyze [--dry-run]` | `intro_skip_analyze_enabled` / `analyze_skip_before_season` |
| **jfhook** | Jellyfin Webhook 插件 → 看完一集 → 停该集做种 + bgm 标看过。也能**反向撤销**：在 Jellyfin / Findroid 里取消勾选「看过」→ 恢复该集做种 + 把该集的 bgm 收藏状态改回未收藏（type 0），点错了再点一下就能复原，不用手动修两处。两个方向由同一个事件判定（`UserDataSaved` + `SaveReason=TogglePlayed`，看 `Played` 真假——**只认显式的 false**，因为 webhook 模板会把不适用的字段渲染成 `""`，「缺失」绝不能被当成「取消了」）；而没看完就停的 `PlaybackStop` 只是中途退出，永远不算撤销。撤销路径与正向走**同一个** `resolve_torrent_target` 收口，所以 `Ancient` 硬闸与 `skip_before_season` 旧番红线是继承来的、不是另写一套；两条腿彼此独立——qB 那步失败也不影响 bgm 那步。撤销是较温和的方向（恢复做种最多多传点上传流量，bgm 标记随时能再标回来），故默认不限速；但在 Jellyfin 里标记**整部剧集**会级联到每一集、一次推来几十条 webhook，需要时可用 `jfhook_reverse_rate_limit_per_min` 给撤销方向（且仅撤销方向）加每分钟上限。调试用 `python anime_rss.py jfhook --dry-run` | `jfhook_port` / `jfhook_reverse_enabled` / `jfhook_reverse_rate_limit_per_min` |
| **事件账本** | 每一集入库都往只增不改的 `events.json` 追加一条（`seq` 单调递增、原子写、保留 `max(最新 500 条, 最近 30 天)`），新番订阅同理。经 `GET /api/events?after_seq=…&limit=…` 提供（按 seq 升序，带 `hasMore`），外部消息中心可用游标跟随、一条不漏——包括它自己离线那段时间（也可直接读文件）。账本条目写在该集硬链接进库那一刻，所以「入库」指的是真的能看了，而非仅仅加入队列；该轮为幂等操作，故每集只播报一次。首次运行会从镜像回填最近 48 小时，账本不会开局全空 | 常开 |
| **Web 控制面板** | 本地仪表盘，整个页面就是一件家具：一张书房里的维多利亚式写字桌。页面中央是桌面的书写区——嵌在木框里的绿色细纹皮革、四周压出的金边双线、四角的皮革压纸角、中间那道摊开的登记簿书脊折痕，以及你最后打开过的那张封面淡淡印在皮革上的影子。书柜的顶线横过窗口，任何宽度下都在。每部番都是立在自己黄铜挂架上的一本精装书——封面是书的正面，书脊带书顶帽、缝线书带、烫印标签栏，有的还压了徽章；布面、烫箔与这些装帧细节都由该番自己的 ## 文件

- `anime_rss.py` —— 除面板外的全部功能；纯标准库，单文件。
  子命令：`list`、`plan`、`apply`、`prune`、`sync`、`watch`、`mark`、`autocomplete`、`resolve`、`dedup`、`premiere`、`analyze`、`auth`、`jfhook`。
- `webui.py` + `static/index.html` —— FastAPI 控制面板，`http://127.0.0.1:8767`。
  面板是一个自足的单文件：CSS 与 JS 全部内联，所以不存在两个资源文件互相错版的可能。
  `webui.py` 用 `Cache-Control: no-cache` 提供它（要求重新校验，而不是让浏览器自己猜一个
  新鲜期），并把每一处 `/static/…` 引用改写成带该文件 mtime 的 URL——对浏览器**已经**持有
  的副本而言，换 URL 是唯一奏效的缓存击穿手段。外壳还把构建戳写在 `<html data-build>` 上；
  跨越一次改动仍开着的标签页会自己发现（`GET /api/version`）并提示重新载入——这正是资源
  URL 版本串救不了的那种情况：陈旧文档本身才是那个「应该去要新版」的人。
- `static/_probe.html`、`static/_states.html` —— 验证台（见下）。放在 `static/` 下是因为
  断言必须与面板同源运行。
- `scripts/` —— `probe.ps1`（断言）、`shot.ps1`（截图）、`states.ps1`（把悬停/聚焦态强制
  画出来再截图）、`bench_server.py` 与 `_bench.ps1`（公共底座）。截图落在 `scripts/shots/`，
  该目录已 gitignore。
- `static/fonts/` —— 面板所用的两套可变字体（EB Garamond、Noto Serif SC），均为 SIL OFL，授权见该目录下的 `LICENSE.txt`。
- `static/brand/` —— 本应用的标识，涵盖各处会索取的所有格式。由脚本生成、绝不手改：五个本地服务的标识由同一个脚本绘制，该脚本放在 Atrium 仓库的 `icons/gen.py`。
- `run_watch*.bat/vbs`、`run_webui*.bat/vbs` —— 隐藏窗口自启动脚本
  （把指向 `.vbs` 的快捷方式放进 `shell:startup` 即可开机自启）。
- `mikan_overrides.example.json` —— 可选的 `bgm_id → mikan bangumiId` 映射，解析器
  最优先查它。面板的手动解析粘贴框会自动写这个文件；只有脚本化/离线场景才需要手动
  编辑（id 见 `mikanani.me/Home/Bangumi/<id>`）。
- `manual_imports.json` —— 一次性导入台账（自动生成、已 gitignore）：面板手动导入的
  种子没有 qB 规则可反查，靠这本 `infohash → bgm subject` 台账让 mark-watched /
  jfhook 仍能认领它们。
- `events.json` —— 自动化事件账本（自动生成、已 gitignore）。只增不改，删掉是丢历史
  而非重建；消费者会发现 `seq` 重新计数并据剩余内容重新同步。
- 运行时缓存（自动生成、已 gitignore、可随时删除，下轮自动重建）：
  `mikan_resolve_cache.json`（bgm_id → mikan 解析结果）、`episode_span_cache.json`
  （逐集放送日程，与面板共用）、`subject_season_cache.json`（不变的开播季度）、
  `heal_pending.json`（Jellyfin 空系列扫描的触发旗标）、`intro_skip_state.json`
  （上次触发 Intro Skipper 分析的时间，丢了最多多触发一次，无其它影响）。

## 验证面板

三个可复用脚本，全部由 `index.html` 内置的假数据集驱动，**不碰正在运行的面板**：

```powershell
pwsh scripts\probe.ps1                      # 断言：中英 x 深浅四轮，外加一轮故障注入
pwsh scripts\probe.ps1 -Lang zh -Theme dark # 只跑一种组合
pwsh scripts\shot.ps1                       # 截图，入场动画已冻结
pwsh scripts\shot.ps1 -Tab schedule -Width 1400
pwsh scripts\states.ps1                     # 把悬停/聚焦态画出来再截图
pwsh scripts\states.ps1 -Scene gauge        # shelf | gauge | long | timetable | picker | all
```

`probe.ps1` 用一个临时端口提供 `static/`，在无头 Chrome 里打开 `_probe.html`，再把探针页
写出的断言读回来。探针在同源 iframe 里用**真实的**指针与键盘事件驱动面板，检查状态确实变了：
指针落在哪一集、指针就走到哪一集，排序键第三次按下必须回到默认顺序，指向某番的一处、其余各处
必须一起点亮，全程控制台保持沉默。**它绝不会打开正在跑的面板。** iframe 是带 `?fixture` 载入的，
该开关把 `fetch` 换成内置数据集，并对一切非 GET 请求**直接拒绝**——这里每一个写接口都会造成
不可逆后果（删掉某番的文件、结束宽限期、写 bangumi 收藏），所以验证跑批必须做到「即使误点也够不着」。

最后一轮带 `?fault=upcoming` 运行，故意让其中一块面板抛异常，并断言它在自己那张卡上贴出了故障条、
且它后面的每一块面板照画不误。

`states.ps1` 存在的理由是：普通截图根本拍不出悬停效果——指针不在任何东西上，所有 `:hover` 规则
都是空的。它对脚本驱动的状态派发真实事件，对纯 CSS 的状态则把页面自己的 `:hover` / `:focus`
规则改写到属性上，所以以后新增的悬停规则无需任何人去维护清单就自动被覆盖。

两个截图脚本都传了 `--force-prefers-reduced-motion`。不加的话无头浏览器会拍下一帧永远不会推进的
入场动画，每张卡都停在 opacity 0，看起来就跟页面没渲染出来一模一样。

## 性能

稳态下一轮 5 分钟同步在**一秒以内**完成（参考环境 ~108s → ~0.8s）。所有联网 pass 共用一个
每轮上下文，每部番最多解析/取日程/查收藏一次；mikan 解析结果跨轮持久化，已建 qB 规则的番
**零** mikan 调用（mikan_id 直接从规则 feed 的 `bangumiId` 读出）。短时负缓存避免每轮重搜
mikan 永不收录的剧场版/特别篇。Jellyfin 空系列 `/Items` 扫描与库文件夹检查改为「仅镜像有变动
或每 N 轮」触发，不再每轮跑。可调项：`resolve_ttl_seconds`（默认 24h，已解析身份的刷新周期；
有规则的番永不重取）、`resolve_negative_ttl_seconds`（默认 30 分钟，未收录的番多久后重搜；设 `0`
关闭负缓存改为每轮实时重搜）、`heal_backstop_passes`（默认 12，Jellyfin 扫描的安静轮兜底周期）。
处于 ANi 宽限期或有手动 override 的番每轮都会强制刷新字幕组名册，故迟到的高优先组绝不会漏掉。

## 部署

1. 环境要求：Windows、Python 3.11+、开启 Web UI 的 qBittorrent（localhost、
   免密），以及可选的 Jellyfin + Webhook 插件。
   面板需要 `pip install fastapi uvicorn`。
2. 复制 `config.example.json` → `config.local.json`，填入你的值
   （bgm 用户 id、mikan cookie、Jellyfin API key、各路径）。
3. 单次运行：`set PYTHONUTF8=1 && python anime_rss.py sync`
   守护进程：`python anime_rss.py watch`（每 5 分钟同步 + jfhook 监听）。
4. 面板：`python webui.py` → 浏览器打开 http://127.0.0.1:8767。

bgm token：用 365 天个人令牌（`bgm_access_token`），或用可自动续期的 OAuth——
在 https://bgm.tv/dev/app 建应用，填 `bgm_client_id`/`bgm_client_secret`，
执行一次 `python anime_rss.py auth`。

## 本工具自动套用的约定

- qB 保存路径 `<bangumi_library>\<YYYY.MM>\<英文番名>`，标签 `<YYYY.MM>`。
- RSS feed 挂在 `<YYYY.MM>` 文件夹下，订阅前会先显式建好该文件夹——
  qBittorrent 5.x 的 `addFeed` 不会自动创建父文件夹（季度文件夹不存在会 409，
  留下一条没有 feed 的空转规则）。
- 每部番只用一个字幕组——mikan 的 RSS 地址本身就是按组区分的。
- 季度：01 / 04 / 07 / 10；季度字符串按字典序比较（`2026.04 < 2026.07`）。
- 开播日落在下一季首日之前 `cour_rollover_days` 天（默认 14）以内的番，算作
  **下一季**，而不是其日历季度——9 月下旬开播的是提前开播的十月番，除首集外
  整段放送都在秋季。设为 0 则退回纯日历季度。规则由 `python test_season.py` 覆盖。
  下面的 `skip_before_season` 红线**刻意不吃这条滚动规则**：它比较的是纯日历季度，
  因此「哪些旧番只读」绝不会因为展示口径变化而改变。
- 破坏性操作（删文件/删规则）只对 `skip_before_season` 及之后的番生效；
  更早的番对本工具严格只读。两类例外仍算「当前」：bgm id 列入
  `pin_current_bgm_ids`（手动逐番开启），以及仍在放送的跨季番（半年番/年番，
  按 bgm 逐集日程，末集放送日 ≥ 今天）。已经播完的长番重新变回只读。
- 上述判断全部来自 bgm 的回答，因此工具严格区分「bgm 回答了，答案是没有」与
  「bgm 根本没回答」：404 是回答，可以缓存；5xx、超时、限流不是，一律不写进任何
  缓存。拿不到回答时该番本轮直接跳过、下轮重试——bgm 连不上不构成关于这部番的证据。

## 安全说明

- `config.local.json` 存放全部密钥，已 gitignore；代码里不硬编码任何敏感信息。
- 任何缓存都不得把失败的查询记成事实。`subject_season_cache.json` 尤其如此：
  它没有过期机制（开播季度本身不变），而季度被误记为未知会被读成「当前番」，
  正是这一步让本该只读的旧番变成可拆除对象。模拟 bgm 故障的行为由
  `python test_bgm_outage.py` 覆盖。
- Jellyfin 联动删除在源库缺失或为空时拒绝执行（防盘未挂载），删除数量异常时中止。
- Web 面板默认只绑 127.0.0.1；只有在可信局域网内才建议设 `webui_host: "0.0.0.0"`
  （面板本身没有鉴权）。
